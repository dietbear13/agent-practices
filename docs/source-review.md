# Сверка упрощения с докладом

Дата: 2026-11-08. Исходное состояние репозитория: `383680f`.
Источник: [презентация Михаила Булгакова](https://docs.google.com/presentation/d/19Km9pqSWkO8MYYQy6hK6UV9t7NFOYNlEDYHKxAOlIKQ).
Прочитан текст всех 25 слайдов, включая таблицы. Текст внутри растровых изображений
не извлекался; содержание иллюстраций отдельно не подтверждено.

Это запись решений о переносе содержания для сопровождающего, а не дополнительный
набор правил для пользователя. Действующие инструкции находятся в практиках.
Уточнение автора от 2026-11-09: экспертные приоритеты могут быть общими для всех
сайтов. Прежняя рекомендация разделять их по клиентам была ошибкой интерпретации.
Исправлены практика, оба сценария структуры, руководство и примеры; сам факт
проверки ссылок эту смысловую ошибку не обнаруживал.
Старые пути ниже обозначают файлы указанной Git-ревизии, а не существующие ссылки.

## Хранение ключей

По запросу автора от 2026-11-10 добавлена шестая
[практика хранения ключей](../practices/secrets.md) и
[образец](../examples/secrets.md). Это развитие руководства по отдельному запросу,
а не утверждение о дополнительном содержании исходного доклада.
Практика охватывает строковые ключи и JSON-файлы, проверку без вывода значений,
перенос, права доступа и действия при раскрытии. Обновлены обе точки входа,
ссылки из Git и карты доступов, образец игнорирования и его проверки.

## Что было потеряно при первом сокращении

Дерево папок и отдельное место результатов регулярных запусков; список задач;
карта доступов и параметры источников; эталоны и извлечение критериев; бриф и план
по этапам; правило о свежих данных; роли постоянных файлов и согласование памяти;
приёмка инструмента на известном ответе; передача файлов между этапами.
Все эти темы возвращены в практики без восстановления установщика.

## Осознанные отличия от прежней реализации

- Слайд 7 предлагает третий повтор как сигнал к регулярности. Сигнал сохранён,
  автоматический порог убран по плану упрощения. Сбор и обработка по устойчивому
  алгоритму закрепляются в коде; экспертные действия остаются инструкциями.
- Старый шаблон запрещал заполнять приоритеты до первой ошибки. На слайде 12
  показаны экспертные установки; такого запрета нет. Приоритеты можно задать заранее.
- На слайдах 13–15 владелец контролирует постоянную память. Это сохранено;
  уже данное поручение обновить согласованные сведения не требует повторного «ок».
- Новая сессия и отдельный исполнитель полезны при больших этапах, но не являются
  условием использования руководства. Численные лимиты длины скиллов и жёсткая
  топология из прежних файлов не перенесены.
- Список сохраняемых результатов оставлен как приём. Автоматическое удаление
  всех неупомянутых файлов не перенесено: отсутствие в списке не доказывает ненужность.
- Правило свежести не заменяется `.gitignore`: игнорируемые данные доступны локально.
- Недоступный источник не доказывает ошибку и не считается успешной проверкой.
  Старый проверяющий ссылок не сверял содержание источника с утверждением.
- Старые числа из `TALK.md` и описания runtime не совпадают с текущим кейсом на
  слайде 11. Они не перенесены как актуальные данные доклада.

пять практик из таблицы выше. В строках кода отмечено назначение механизма и
сохранённая идея; это сверка содержания, а не аудит корректности удалённого кода.

## Проверка сценариев после восстановления

| Сценарий | Ожидаемое действие по руководству |
|---|---|
| Пустая папка, одна разовая задача, Git отсутствует | Собрать вводные и при необходимости план; создать только нужную папку задачи; не требовать Git, установку или весь набор файлов |
| Ежемесячный отчёт в существующем проекте | Найти инструкцию и общий скрипт, сохранить новый запуск отдельно в outputs; при ошибке выгрузки не брать прошлый месяц молча |
| Один сайт с существующими файлами | Найти и дополнить действующие документы по их путям, не создавать второй комплект и не требовать папку sites |
| Несколько сайтов, один PRIORITIES.md | Прочитать общие приоритеты и досье выбранного сайта; общие скиллы и инструменты работают с данными этого сайта; локальные копии приоритетов не нужны |
| Повтор разовой задачи | Предложить выделить проверенный алгоритм и инструкцию; не переносить старые выгрузки в общий код |
| Новая сессия после этапа | Прочитать план, решения и сохранённый результат; проверить вход следующего этапа |

## Выбор MCP и few-shot

По запросу автора добавлены критерии готового MCP, собственного сервера и скрипта
в практику о скиллах. Неизменяемые API-настройки закрепляются в коде или конфигурации
сервера, переменные остаются аргументами LLM; отдельно учтены разные сайты и запрет
обходить фиксированные настройки свободными параметрами. Пример вызова учебный,
он не заявлен как действующая схема какого-либо API.

Повторно прочитан текст слайдов 9, 10 и 18. В практику задач добавлен необязательный
few-shot: инструкция, правильные и неправильные примеры, пояснения к ним.
Конкретные пары редакторской правки составлены для руководства по приёму слайда 18.
Образец скилла теперь содержит два примера сверки сумм; проверка результата
отдельно требует нового входа, а не только воспроизведения показанного примера.
