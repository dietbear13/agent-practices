# Практика: агент проверяет агента — сначала кодом, потом по рубрике

> Раздел доклада: 10 «Контроль качества: агент проверяет агента», 10.2 «Передача
> спец → ИИ → спец».

## Проблема

Самооценка автора работы не является проверкой: он унаследует собственные слепые
зоны. «Проверь, всё ли хорошо» каждый раз даёт разный результат и не ловит ничего
конкретного. А проверка, у которой есть только PASS и FAIL, постепенно сползает к
PASS: зелёный отчёт приятнее.

## Как понять, что это про вас

- Агент сам проверяет свою же работу в том же окне.
- Нет рубрики: проверка формулируется заново при каждом запуске.
- Модель «проверяет» ссылки и числа рассуждением, а не кодом.
- Вердикт проверки остаётся в чате и через неделю не восстановить, что проверяли.
- Результат передаётся другому специалисту текстом из чата, без фиксированного формата.

## Минимальная правка

1. **Сначала кодом** — живые ли ссылки, сходятся ли числа, валиден ли формат. Упало —
   дальше не идти: модели незачем рассуждать о тексте с мёртвыми ссылками.
2. **Рубрика из проверяемых пунктов.** «Текст должен быть хорошим» — не пункт.
3. **Проверяющий со свежим контекстом** — получает только артефакт и рубрику, без
   рассуждений автора.
4. **Три исхода, а не два:** PASS, FAIL и «нужно решение человека». Третий — самый ценный.
5. **Вердикт — файлом** рядом с артефактом.

Между людьми передаётся артефакт фиксированного формата, и первый шаг принимающего —
проверка формата кодом. Невалидно — возврат, а не молчаливая обработка мусора.

## Чего не делать

- Не запускать проверку на всём подряд: она нужна там, где ошибка дорогая (факты о
  компании, цифры для клиента, тексты на публикацию).
- Не пересказывать проверяющему, «на что обратить внимание»: ровно это и ломает
  свежий контекст.
