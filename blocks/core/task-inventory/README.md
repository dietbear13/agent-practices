# Практика: список задач и карта доступов

> Раздел доклада: 8 «Как и из чего собирать агентов», 4.1 «Доступы».

## Проблема

Задача рождается разовой и становится регулярной на третьем повторе — но этот
момент не наступает сам, если повторы никто не считает: каждый раз кажется, что
«ну это последний раз вручную». А без карты доступов агент планирует работу через
сервис, которого у проекта нет, и узнаёт об этом в середине задачи.

## Как понять, что это про вас

- Нигде не записано, какие задачи агент решает регулярно, а какие делал один раз.
- Одну и ту же выгрузку агент каждый раз собирает заново, в новом формате.
- Агент предлагает «выгрузить из GSC» или «посмотреть в Топвизоре», а доступа туда нет.
- В правилах проекта перечислены сервисы, но не сказано, к чему доступа **нет**.
- Несколько подключённых сервисов умеют одно и то же (частотность, позиции), и
  не зафиксировано, каким пользоваться по умолчанию.

## Минимальная правка

1. Список задач с двумя разделами — регулярные (период + формат результата) и
   разовые (счётчик повторов). Правило: на третьем повторе задача перестаёт быть
   разовой, агент говорит об этом сам.
2. Карта доступов, где отсутствие доступа записано так же явно, как наличие:
   пустая строка значит «не выясняли», и агент будет пробовать снова; «нет» значит
   «не предлагать».
3. Строка «чем по умолчанию» для задач, которые умеют несколько сервисов.

Если у пользователя уже есть файл правил — достаточно короткого раздела в нём или
двух небольших файлов рядом. Ключей в карте нет никогда: только идентификаторы
(номер счётчика, адрес сайта).

## Чего не делать

- Не заполнять список задачами «на будущее» с полями: достаточно названий, поля
  появятся, когда дойдёт очередь.
- Не называть задачу регулярной без зафиксированного формата результата: без
  формата агент выберет его сам и каждый раз новый.
