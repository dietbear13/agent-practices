# Практика: папка на задачу, манифест и чистильщик

> Раздел доклада: 1.3 «Проблема 2: замусоривание папок», 7 «Гигиена разовых задач».

## Проблема

После каждого запуска в папке остаются временные файлы, черновики и
«отчёт_финальный_2.csv». При следующем запуске агент изучает артефакты старых
задач, тратит на это токены и время, а иногда принимает их за факты. Разобрать
вручную, что ещё нужно, а что мусор, через месяц уже невозможно.

## Как понять, что это про вас

- В корне проекта лежат выгрузки, csv, скриншоты и скрипты разовых задач.
- Нет единого места и шаблона имени для результатов задач.
- Агент в начале работы читает файлы, оставшиеся от прошлых задач.
- `git status` показывает много незакоммиченных файлов, о которых никто не помнит.

## Минимальная правка

1. **Своя папка на каждую разовую задачу** с шаблоном имени
   `tasks/ГГГГ-ММ-ДД-имя/`; работа и результат живут там же.
2. **Манифест результатов** (`manifest.json`): код, который пишет результат, сам
   его регистрирует. Тогда понятно, что результат, а что черновик.
3. **Чистильщик**: удаляет из папки задачи всё, чего нет в манифесте. По умолчанию
   только показывает, удаляет по явному флагу.
4. `tasks/` — в `.gitignore`: git следит за системой, а не за результатами.

Самый дешёвый вариант — правило в файле правил: «разовая задача — своя папка в
`tasks/` с датой в имени, в корень ничего не класть».

## Что можно взять отсюда

| Файл | Что это | Когда брать |
|---|---|---|
| [tools/new_task.py](tools/new_task.py) | заводит `tasks/ГГГГ-ММ-ДД-имя/` с `manifest.json` и `report.md` | разовых задач много |
| [tools/cleanup_task.py](tools/cleanup_task.py) | удаляет всё, чего нет в манифесте; без `--apply` только показывает | папки задач уже замусорены |

Оба — один файл на стандартной библиотеке Python, без зависимостей.

## Чего не делать

- Не чистить по списку расширений: через месяц `.csv` окажется и результатом, и
  мусором. Отличать умеет только манифест.
- Не переносить результаты в корень проекта «чтобы было под рукой».
