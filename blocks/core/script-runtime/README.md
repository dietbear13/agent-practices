# Практика: регулярное — кодом, критичное — в файле, а не в промпте

> Раздел доклада: 5.3 «Исполнение заготовленных py-скриптов», 3.6 «Что ещё обязательно
> (эксплуатация)», 4.1 (секреты читает код).

## Проблема

Регулярная задача, которую каждый раз заново делает агент, каждый раз выглядит
по-новому и стоит дороже. А всё, что отличает надёжный скрипт от разового запуска —
остановка по лимиту, устойчивость к перезапуску, отметка «данные неполные», —
нельзя держать просьбой в промпте: текст переживает не всякую сессию.

Замер из доклада: одна и та же выгрузка из Метрики через MCP — 69 секунд и $0.67,
готовым скриптом — 42 секунды и $0.45.

## Как понять, что это про вас

- Задача повторяется каждую неделю/месяц, но выгрузку каждый раз собирает агент.
- В промпте написано «не больше N запросов», «не повторяй при ошибке», «не бери
  старую выгрузку» — и это иногда нарушается.
- Скрипт при обрыве начинает сначала и платит второй раз; при перезапуске плодит дубли.
- Выгрузка вернула ноль строк или обрезанную пагинацию, а отчёт построен как ни в чём не бывало.
- Ключи подставляет модель, а не скрипт.

## Минимальная правка

Скрипт регулярной задачи держит кодом четыре вещи:

- **стоп-кран** — лимит шагов, времени или денег, после которого зовут человека;
- **дедупликация** — помнит обработанное, перезапуск не платит второй раз;
- **метка качества** — ноль строк, подозрение на обрезку или семплирование → `degraded`,
  и это видно раньше результата;
- **ретраи, которые не выжигают квоту** — `4xx` не повторяются, `429` — только по
  `Retry-After`.

Ключи читает только скрипт; модель их не видит. Знание о лимитах сервиса (например,
не больше 9 потоков при лимите в 10) зашивается в скрипт: агент его сам не угадает.

## Что можно взять отсюда

| Файл | Что это | Когда брать |
|---|---|---|
| [tools/runtime.py](tools/runtime.py) | `Budget`, `Checkpoint`, `QualityMetadata`, `classify_error`, `read_secret` — один файл на стандартной библиотеке | есть регулярные скрипты без этих защит |

Брать можно целиком или по одному классу — файл ни от чего не зависит.

## Чего не делать

- Не переводить в скрипт задачу без зафиксированного формата результата: сначала формат.
- Не переводить в скрипт разовую задачу «на будущее»: сигнал — третий повтор.
