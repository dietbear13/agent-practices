# Практика: скилл, агент или мультиагент — по сигналу, снизу вверх

> Раздел доклада: 1.4 «Какие есть варианты использования ИИ», 1.5 «Когда упаковывать
> в скиллы, когда в отдельных агентов», 3.4 «Мультиагентность нужна не везде».

## Проблема

По умолчанию делается красиво и дорого: агент-выгрузчик, агент-аналитик и
агент-отчётчик там, где хватает одного агента со скиллами. Каждый лишний стык —
место, где теряется контекст и умножается ошибка. А скиллов становится так много,
что часть молча выпадает из списка, и модель о них не знает.

## Как понять, что это про вас

- Несколько субагентов передают друг другу результат по цепочке, без центра и без
  проверки формата на входе.
- Субагенту отдана задача, следующему шагу которой нужен сырой результат целиком
  (сама таблица, а не пересказ).
- Скилл длиннее ~75 строк, или один скилл делает несколько этапов с разными
  форматами результата.
- Скиллов много, и суммарная длина их описаний (`description`) — тысячи символов.
- На вопрос «зачем этот агент» нет записанного ответа.

## Минимальная правка

Лестница форм, подъём только по сработавшему сигналу:

| Ступень | Когда |
|---|---|
| 0. Один скилл (+ скрипт) | один источник данных, один формат результата |
| 1. Агент с короткими скиллами | 2–4 этапа, следующему нужен материал предыдущего целиком |
| 2. Оркестратор + субагенты | этап даёт много сырья, которое дальше не нужно, или подзадачи независимы; нужен проверяющий со свежим взглядом |
| 3. Этап — отдельная сессия | задача не помещается в одно окно; состояние — в `PLAN.md` |

Запреты: субагент не вызывает субагента (только звезда); у субагента есть формат
возврата, и принимающий проверяет его кодом; один скилл — один этап — один формат.

## Что можно взять отсюда

| Файл | Что это | Когда брать |
|---|---|---|
| [files/topology.json](files/topology.json) | ступени, сигналы подъёма и запреты данными | решить спор «нужен ли тут мультиагент» |
| [tools/choose_topology.py](tools/choose_topology.py) | считает низшую обоснованную ступень и объясняет отказ подняться выше | хочется формального ответа, а не мнения |

```
python choose_topology.py --stages 3 --volume large --needs-review
```

## Чего не делать

- Не начинать с «красивой архитектуры, упростим если что»: упрощение на практике
  не происходит никогда.
- Не лечить нерешаемую задачу удлинением скилла: дело во входных данных и в том,
  показан ли эталон результата.
