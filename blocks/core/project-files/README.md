# Практика: правила проекта, приоритеты и граница git

> Раздел доклада: 3.1 «Агенты не умеют хорошо делать приоритизацию», 4.1 (секреты),
> 7 «Гигиена разовых задач».

## Проблема

Три болезни сразу. Агент не умеет в приоритеты: просили аудит мета-тегов —
получили отчёт про длину description, а действительно важное утонуло. Папки
превращаются в свалку, и агент читает старые артефакты как факты. Ключи попадают
в промпты и файл правил, а оттуда — в контекст модели.

## Как понять, что это про вас

- Файл правил (`CLAUDE.md`, `AGENTS.md`) длиннее ~150 строк или содержит выводы
  прошлых аудитов, результаты задач, гипотезы — то, что не управляет будущей работой.
- Есть файл приоритетов/запретов, заполненный заранее «на всякий случай», а не
  после реальных ошибок агента.
- Ключи или токены лежат в файле правил, в скиллах или в промптах; агенту
  разрешено читать `.env`.
- В `.gitignore` нет `.env`, а результаты задач (`outputs/`, выгрузки) коммитятся
  вместе со скриптами.
- `git status` показывает десятки незакоммиченных файлов неизвестного назначения.

## Минимальная правка

1. **Файл правил короткий.** Он грузится в каждую сессию. В нём — только то, что
   управляет будущей работой: где что лежит и 3–5 правил, которые нарушают чаще
   всего. Выводы аудитов живут в папках задач, иначе через полгода старые
   гипотезы вернутся как факты.
2. **Приоритеты — пустыми.** Строка «не тратить фокус на …» добавляется только
   после того, как агент реально принёс мусор. Список запретов из головы съедает
   фокус так же, как мусор, от которого защищает.
3. **Ключи читает только код.** Правило «не открывай `.env`», значения — только в
   `.env`, имена — в `.env.example`.
4. **Git следит за системой, а не за результатами:** скиллы, скрипты, правила — в
   git; `tasks/`, `outputs/`, `temp/`, `.env` — нет. Незакоммиченные файлы — датчик
   утечки: если их много, что-то пишет не туда.

Обычно это правка существующего файла правил и `.gitignore`, а не новые файлы.

## Чего не делать

- Не переписывать файл правил пользователя целиком под этот шаблон: добавить
  недостающие правила, убрать то, что не управляет работой.
- Не заполнять приоритеты заранее «по опыту» — даже хорошими формулировками.
