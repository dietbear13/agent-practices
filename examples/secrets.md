# Образец хранения доступов

Адаптируйте к существующему хранилищу и способу запуска. Все значения ниже пустые
или учебные; реальных ключей в образце нет.

## Шаблон окружения без секретов

В Git можно хранить `.env.example`:

```dotenv
REPORT_API_KEY=
REPORT_CREDENTIALS_FILE=
```

В локальном окружении задайте строковый `REPORT_API_KEY` и абсолютный путь
`REPORT_CREDENTIALS_FILE` к закрытому JSON-файлу. Это разные типы доступа;
потребителю может быть нужен только один из них. Реальный `.env` не копируйте
в документацию. Не вставляйте JSON в шаблон.

## Получение в Python

```python
import os
from pathlib import Path


def api_key():
    value = os.environ.get("REPORT_API_KEY")
    if not value:
        raise RuntimeError("Не задан REPORT_API_KEY")
    return value


def credentials_path():
    value = os.environ.get("REPORT_CREDENTIALS_FILE")
    if not value:
        raise RuntimeError("Не задан REPORT_CREDENTIALS_FILE")
    path = Path(value)
    if not path.is_absolute() or not path.is_file():
        raise RuntimeError("Проверьте файл REPORT_CREDENTIALS_FILE")
    return path
```

Передайте результат нужной функции штатному клиенту сервиса. Пример не загружает
`.env`, не проверяет права ОС и не подтверждает действительность доступа.
Не печатайте возвращаемый ключ, содержимое JSON, заголовки авторизации или
объекты клиента, которые могут их содержать. Обработчик ошибок клиента тоже
должен исключать секреты из логов.

## Запись в карте доступов

| Сайт и окружение | Сервис | Права | Источник доступа | Владелец | Проверка |
|---|---|---|---|---|---|
| alfa, тест | API отчётов | Чтение отчётов | `REPORT_API_KEY`, окружение процесса | Владелец проекта | Не проверен |
| alfa, тест | Сервисный аккаунт | Чтение выбранного ресурса | `REPORT_CREDENTIALS_FILE`, закрытый локальный файл | Владелец проекта | Не проверен |

## Фрагмент действующих правил для агента

```text
Значения ключей и содержимое файлов учётных данных не читай в контекст и не
включай в команды, ответы, отчёты или логи. Используй названия переменных
и ссылки на записи принятого хранилища. Секреты потребляет локальный процесс.
При разборе хранения сначала проверяй пути, права и статус Git; содержимое
проверяй только локальным инструментом, выводящим путь, строку и тип находки
без значения. При случайном раскрытии не повторяй значение, сообщи владельцу.
Не проси прислать ключ в чат. Для разных сайтов и окружений выбирай
соответствующий доступ по карте источников.
```

Для игнорирования используйте [фрагмент gitignore](gitignore.txt), адаптировав
точные пути. Порядок поиска, исправления и проверки описан
в [практике хранения ключей](../practices/secrets.md).
