# Тезисы доклада

**«Как и из чего собирать ИИ-агентов, чтобы не стрелять из пушки по воробью и не
попасть себе в ногу».** Короткая версия по разделам; у каждого раздела — ссылка на
практику с примерами файлов.

Главный тезис: **критичные операции — обычным кодом, не моделью.** Расчёты,
валидации, повторные запуски без дублей, работа с ключами — детерминированные
функции, а не просьба к агенту сделать работу за себя.

## 1. Из чего выбирать

- **Один промпт + инструменты** — дёшево и предсказуемо; для одношаговых вопросов
  без требований к формату.
- **Workflow** (жёсткая цепочка шагов, модель в узлах) — дороже, но предсказуемо и
  легко тестируется: агент со скиллами выгрузок на готовых python-скриптах и скилл
  анализа поверх.
- **Агент** (модель сама решает, что вызвать) — гибко, но недетерминированно: без
  заготовленных скиллов пишет временные скрипты и отвечает в удобном себе формате.
- **Мультиагентная система** — только когда задача не помещается в один контекст
  без потери качества.

Скилл или агент: нужен ли вызывающему сырой промежуточный материал целиком? Нужен —
скилл (работает в общем окне). Достаточно вывода — агент (промежуточное умирает
вместе с его окном). Начинать с простого и усложнять по итогам прогонов.
→ [Практика: форма системы](blocks/core/skill-design/README.md)

## 2. На что влияет плохо собранный агент

Не только деньги. **Скорость:** на одной и той же выгрузке из Метрики скрипт против
MCP — 42 с против 69 с и $0.45 против $0.67 (−39% времени, −32% денег; один замер
автора). **Качество:** раздутый контекст ухудшает ответы. **Масштаб:** на одном чате
разница копеечная, на агентстве с десятками клиентов и ежедневными прогонами — бюджет.

## 3. Типовые ошибки и иллюзии

- **Агенты не умеют в приоритеты.** Аудит мета-тегов превращается в отчёт про длину
  description, важное тонет. Лечится явным списком того, что не является проблемой,
  — но только по итогам реальных ошибок.
  → [Практика: правила проекта](blocks/core/project-files/README.md)
- **Модули вперёд задач.** Сначала список задач, потом инструменты, потом агенты и
  скиллы — не наоборот.
  → [Практика: задачи и доступы](blocks/core/task-inventory/README.md)
- **Иллюзия переносимости.** Чужая автоматизация неудобна: задачи, подходы и форматы
  у всех разные, а специалисту важно ощущение контроля. Переносятся нижние слои —
  скрипты, скиллы, регламенты, — а верхушка адаптируется под себя.
- **Мультиагентность нужна не везде.** Выгрузчик, аналитик и отчётчик отдельными
  агентами там, где хватает одного агента со скиллами, — лишние стыки и токены.
  Если нужна — только звезда: оркестратор в центре, без цепочек агент → агент.
- **Ошибки через недели:** качество падает с ростом контекста; при сжатии контекста
  выпадают стоячие правила; инструменты разрастаются и перекрывают друг друга;
  меняются схемы и API, а агент узнаёт последним; модель и промпты тихо дрейфуют;
  агенты падают тихо — правдоподобным ответом вместо ошибки.
- **Эксплуатация:** повторный запуск не создаёт дублей; долговременная память — только
  то, что продолжает ограничивать будущую работу; у регулярного прогона жёсткий
  бюджет шагов, времени и денег. Минимум без DevOps — ~30 строк Python и cron.
  → [Практика: регулярное кодом](blocks/core/script-runtime/README.md)

## 4. Агентство и инхаус

У агентства есть регламенты и повторы внутри зон — автоматизировать проще и можно
докручивать итерациями. У инхауса часто одна итерация, поэтому серые зоны надо
продумать до старта. Дешёвая страховка: пилот на срезе (20 страниц из 10 000) и
промпт «найди серые зоны» — час вместо недели.

**Доступы:** в проекте записано, что где искать (номера счётчиков, проектов) и к
чему доступа нет. Секреты — никогда в промпты и файл правил: ключи читает скрипт.
Один клиент — один проект — свой контекст.

## 5. Три пути работы с сервисами

| | Готовые MCP с гитхаба | Свои MCP под узкие задачи | Готовые py-скрипты |
|---|---|---|---|
| Повторяемость | разовая, исследование | регулярная, нужен диалог | регулярная, формат известен |
| Кто пользуется | я сам | команда | команда, cron |
| Навык кода | не нужен | желателен | не нужен — пишет агент, вы принимаете |
| Цена и скорость | дорого, медленно | средне | дёшево, быстро |

«Спросить один раз — MCP с гитхаба; спрашивать каждую неделю — свой инструмент;
спрашивать каждый день без себя — скрипт по крону». Чужие MCP — только на чтение и
без доступов к продакшену. → [Практика: чужое не как есть](blocks/core/adopt-external/README.md)

## 6. Почему куча MCP — плохо

Определения всех инструментов висят в контексте всегда, форматы ответов плавают,
подтягиваются старые уточнения. Надёжнее набор скриптов с предсказуемым ответом, а
где нужно — UI, который вызывает только зашитые пайплайны: это осознанное
ограничение свободы агента, а не украшение.

## 7. Гигиена разовых задач

Своя папка на разовую задачу; манифест итоговых файлов и чистильщик всего
остального; одна папка сохранения с шаблоном имени; `.gitignore` для задач и
временных файлов — и незакоммиченные файлы как датчик утечки.
→ [Практика: папка на задачу](blocks/core/task-folder/README.md)

## 8. Как собирать

1. Один сайт или несколько.
2. Какие задачи регулярные, какие разовые; для разовых — отдельная папка; в git
   только общие инструменты.
3. Какие инструменты есть и к чему открыт доступ в каждом проекте.
4. Скиллы по зонам (аналитика, семантика, техничка, отчёты руководителю); в каждом —
   какими инструментами можно пользоваться.

## 9. Большие задачи

План файлом с чекбоксами → серые зоны и вопросы по каждому этапу → этап = новая
сессия («прочитай PLAN.md, найди первый невыполненный этап») → отметка в плане.
Большие таблицы — батчами с чекпоинтом обработанных ID.
→ [Практика: план и серые зоны](blocks/core/plan-mode/README.md)

## 10. Агент проверяет агента

Сначала проверки кодом; проверяющий получает артефакт и рубрику, но не рассуждения
автора; рубрика вместо «проверь»; флагать только то, что влияет на корректность;
требовать артефакт проверки, а не самооценку. Между специалистами передаётся
артефакт фиксированного формата, и первый шаг принимающего — проверка формата кодом.
→ [Практика: проверка](blocks/core/verify/README.md),
[Практика: досье](blocks/core/dossier/README.md)

## 11. Дорогие задачи останутся

Слияние текстов по смыслу и агентный ресёрч дёшево не сделать. Ужимать можно:
дешёвый пре-фильтр кандидатов, массовое — батчами, повторяющиеся инструкции — в кэш.

## 12. Выводы

Где нужен UI: задача повторяется чаще раза в неделю? больше трёх шагов в фиксированной
последовательности? пользователь не автор? Три «да» — UI, два — скилл или команда,
одно и меньше — отчёт в чате.

**Задачи вперёд модулей; критичное — кодом; свобода агента — по заслугам; артефакт
проверки, а не самооценка.**

→ [Шпаргалка из четырёх промптов](CHEATSHEET.md)
